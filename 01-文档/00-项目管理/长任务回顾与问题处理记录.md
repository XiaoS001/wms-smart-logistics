## 二、逐项说明

### P1　命令行反复失败 `0x3221225794` ★根因最有价值的一条

- **现象**：本会话中 `pwsh` 工具执行任何命令都返回退出码 `3221225794`（十六进制 `0xC0000142`，即 `STATUS_DLL_INIT_FAILED`），无任何输出。
- **初期误判**：结合工作区曾有权限问题的印象，怀疑是工作区 ACL 导致沙箱无法启动子进程。
- **真正的根因**：**本机从未安装过 PowerShell 7**。工具名 `pwsh` 指向的可执行文件不存在，启动失败被报成 DLL 初始化失败。
  - 全盘扫描 `pwsh.exe` → 一个都没有
  - 只有 Windows PowerShell 5.1（`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`）
  - 反证：`powershell.exe` 以及 `cmd /c` 在执行提权命令时**都能正常工作**
- **解决**：安装 PowerShell 7.6.6（LTS）。安装后 `pwsh` 应可正常使用。
- **经验**：`0xC0000142` 既可能是"缺 DLL"，也可能是"可执行文件根本不存在"。下次先确认工具本身是否装了，再怀疑权限。

### P2　工作区权限修复

- **过程**：首次请求提权执行权限诊断脚本被拒；后经用户批准执行。
- **结论**：`diagnose-windows-sandbox-acl` 脚本判定 `NOT_THIS_CLASS` —— `D:\DeepSeekXM\XM01` 及其上级目录的 `WRITE_DAC`、`WRITE_OWNER` 权限齐全，**未做任何 ACL 改动**。
- **报告存档**：`D:\DeepSeekXM\dsh-acl-recovery\acl-report-*.jsonl`

### P3　Word 文档中文乱码

- **现象**：`python-docx` 读出的中文经 PowerShell 控制台回显后全是乱码（如 `ʵ��Ŀ��`）。
- **根因**：Windows 控制台代码页（GBK）与 Python 输出的 UTF-8 不匹配，输出被二次错误解码。
- **解决**：脚本改为**把结果写入 UTF-8 文件**，再用文件读取工具读——彻底绕开控制台编码。
- **已固化**：本项目所有文档解析脚本都采用"落盘 + 读文件"模式。

### P4　Maven 镜像配置未生效

- **现象**：脚本日志显示 `settings.xml patched`，但检查发现配置没生效。
- **根因**：用正则 `</settings>` 定位插入点，却命中了**注释里的 `</mirrors>`**，配置被插进注释块。
- **解决**：改用 XML API 精确操作，并在写入后**重新解析校验**（确认 mirror 条目存在）。
- **附带发现**：PowerShell 的 XML DOM 调用在本机异常（`CreateElement('mirrors')` 返回 `null`），最终改用 Python 生成配置。
- **经验**：改配置文件后必须**读回校验**，不能只看日志说"成功"。

### P5　建库 SQL 全部失败

- **现象**：`Access denied for user '-pWms@2026Root'@'localhost'` —— 用户名里居然带了密码。
- **根因**：`cmd.insert(2, "-p"+pwd)` 把密码参数插到了 `-u` 之前，mysql 客户端把 `-pWms@2026Root` 当成了用户名。
- **解决**：改为按正确顺序构造命令：`mysql -u USER -pPWD --port=... -e SQL`；补跑并做了建表/插入/查询/删除冒烟测试。

### P6　实验脚本依赖缺失

- **现象**：实验跑完 4 组后，写报告时报 `No module named 'tabulate'`；图表报 `No module named 'matplotlib'`。
- **解决**：① 自写 `md_table()` 函数替代 `DataFrame.to_markdown`，不再依赖 `tabulate`；② 安装 `matplotlib 3.11.2` 用于出图（实测中文渲染正常）。
- **经验**：环境是 DSH 内置 Python，第三方库需显式确认；能用标准库解决就不引入依赖。

### P7　`.ps1` 中文乱码

- **现象**：`status-mysql.ps1` 报 `Unexpected token 'mysqld'`，且中文显示为 `mysqld 鏈繍琛屻€?`。
- **根因**：Windows PowerShell 5.1 对**无 BOM 的 UTF-8** 脚本按 ANSI（GBK）解析，中文字节被错误解码后破坏了引号配对。
- **解决**：统一给工作区所有 `.ps1` 加 UTF-8 BOM（7 个文件），修复后脚本正常运行。
- **经验**：给这台机器写 `.ps1` 必须带 BOM。

### P8　`.cmd` 中文乱码

- **现象**：`mvn.cmd` 的中文注释被 cmd.exe 解析成命令，报 `'脚本（不依赖当前窗口的' is not recognized`。
- **根因**：cmd.exe 按系统 ANSI（GBK）读取批处理；文件是 UTF-8。
- **解决**：① 项目内 `.cmd` 转为 GBK 编码（在真实 cmd 窗口中文正常）；② 另外在**纯英文路径** `D:\Dev\scripts\` 放了 ASCII 版包装脚本，供自动化调用（避开中文路径的编码干扰）。
- **验证**：`D:\Dev\scripts\mvn.cmd -v` → `Maven 3.9.16 + Java 1.8.0_504` ✅

### P9　算法代码缺陷（本项最重要）★

自检脚本抓到两个真实缺陷，**如果不做自检就会带着错数据写进论文**：

1. **`abc_greedy` 溢出逻辑错误**
   - 现象：`ValueError: shape mismatch: value array of shape (70,) could not be broadcast to indexing result of shape (127,)`
   - 根因：B 类商品数（58）超过中区容量时，溢出处理用固定切区，导致容量不匹配。
   - 修复：改为**逐类占用"剩余最近货位"**，天然处理溢出。
2. **S 型与最大间隙策略漏记拣货点**
   - 现象：路线只包含巷道折返点，**没有经过巷道内的拣货点**，导致距离偏小、对比失真。
   - 根因：把策略抽象成了"只记折返点"，但距离计算与合法性校验要求路线包含全部拣货点。
   - 修复：重写两个策略，路线按真实经过顺序包含全部拣货点，并加去重；新增自检项"路线必须覆盖所有拣货点"。
- **复验**：修复后 40+ 项自检全部通过 ✅
- **经验**：**启发式策略的"路线合法性"必须显式校验**，否则算出来的距离没有意义。

### P15–P21　交付验收阶段发现的问题（2026-10-11）

详细记录见 `01-文档\03-进度检查\交付验收与缺陷修复记录.md`。此处只记要点。

**P15　后端完全没有权限校验 ★与 P9 并列最重要的两条**

数据库定义了 17 个权限编码、登录接口也返回权限列表，但**项目中不存在任何
过滤器、拦截器或切面**——权限只作为数据存在，从未与请求关联。
后果：任意登录用户可调用全部接口。实测拣货员新增商品返回 `200`（应为 `403`）。

解决：新增 `UserContext`（ThreadLocal 上下文）、`AuthInterceptor`（令牌解析 +
权限校验）、`WebMvcConfig`（注册到 `/api/**`）。
**每次请求都从数据库读权限**，因此角色权限调整后立即生效、无需重新登录。
白名单仅登录与健康检查。

**P19　权限不闭合**

`location:view` 的角色打不开库位页面：页面必须先调 `/api/warehouses` 才能知道
查哪个仓库，而该接口要求 `warehouse:view`；同理 4 个业务页面调用的
`warehouseApi.detail` 也要求 `warehouse:view`。
**权限没有对"页面实际执行的操作"闭合**，只持有一个权限的角色反而寸步难行。

关键判断：`GET /api/warehouses`（列表）**本来就返回同样的布局参数**，
所以把"明细"接口设成更高权限**什么都没保护**，纯粹制造耦合。
于是把仓库的**读**接口（列表 + 明细）改为仅需登录，增删改仍要求
`warehouse:view`，前端 `/base/warehouse` 路由也仍由它守卫——
**最小权限完全保住**（拣货员读 200、写 403、打不开管理页）。

**P20　测试工具的静默失败**

演示后端占用 8080 时，批量验证脚本会在启动阶段失败并立刻退出，
表现为「只跑 4 秒、0 项检查、退出码 1」，**看起来像代码坏了**。
已加端口前置检查，明确报错并给出解决命令，退出码用 4 与测试失败区分。

> 这一类问题的价值在于：**测试工具本身的可靠性也是交付质量的一部分**。
> 一次静默失败会让人对整套验证结果失去信心。

**新增的防回归设施**：`verify-permission-matrix.ps1`（87 项）
把「权限闭合性 + 最小权限」固化为可重复检查，防止同类问题再次出现。
